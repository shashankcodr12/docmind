01 / The Problem

Why Traditional Document Search Fails

01

Keyword Blindspots

Standard Ctrl + F search only matches literal character strings. It misses synonyms, paraphrased technical concepts, and translated terminology.

02

LLM Hallucinations

Public LLMs have fixed knowledge cutoffs and no visibility into private PDFs. When asked about domain-specific files, standard models make up plausible but completely false facts.

03

Context Window Overload

Stuffing entire 200-page PDFs into an LLM prompt costs massive tokens, introduces high latency, and leads to the "Lost in the Middle" problem where the model misses crucial details.

💡

The Opportunity for RAG

Instead of retraining billion-parameter models, we dynamically retrieve the precise 3–5 paragraphs relevant to the user's question and feed them as verifiable context.

02 / The Solution

Understanding RAG (Retrieval-Augmented Generation)

R
1

Retrieve

Vector Similarity Search

Convert the user's prompt into embeddings and search PostgreSQL pgvector to find the top-K semantically closest chunks.

A
2

Augment

Prompt Context Injection

Wrap the user's question inside a strict guardrail prompt: "Answer strictly using ONLY the following verified document excerpts..."

G
3

Generate

Real-Time LLM Streaming

Google Gemini 2.5 Flash processes the augmented prompt and streams back an accurate, cited answer token-by-token.

❌ Fine-Tuning: Expensive ($$$), takes days of GPU training, obsolete as soon as documents change.
✅ RAG: Instant updates, zero retraining, strict source citations, runs on standard database storage.

05 / The Core Math

Vector Embeddings & Cosine Similarity

Cosine Similarity Formula

Measures the cosine of the angle between two high-dimensional vectors, independent of vector length:

$$\text{Similarity}(\mathbf{A}, \mathbf{B}) = \frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\| \|\mathbf{B}\|} = \frac{\sum_{i=1}^{768} A_i B_i}{\sqrt{\sum_{i=1}^{768} A_i^2} \sqrt{\sum_{i=1}^{768} B_i^2}}$$
  • +1.0: Exactly identical semantic meaning
  • 0.0: Orthogonal (completely unrelated concepts)
  • -1.0: Directly opposite meaning

Why HNSW Indexing?

Hierarchical Navigable Small World (HNSW) constructs a multi-layer graph where top layers have long links for fast skipping and bottom layers have dense links for precise retrieval.

Flat Sequential Scan O(N) - Slow (1-2s)
IVFFlat Index Low recall on updates
HNSW Index (DocMind) O(log N) - Ultra Fast (15ms)
-- Supabase SQL vector definition
CREATE TABLE public.vector_store (id uuid, content text, metadata jsonb, embedding vector(768));
CREATE INDEX ON vector_store USING hnsw (embedding vector_cosine_ops);

11 / Viva Q&A

Professor Defense Questions & Answers

Click any card to reveal answer

Q1: Why HNSW indexing instead of IVFFlat?

+

Answer: IVFFlat requires periodic retraining when new vectors are added, otherwise search recall degrades severely. HNSW constructs a multi-layer graph that dynamically accommodates incremental inserts while maintaining $O(\log N)$ search speed.

Q2: Why not store vectors in Pinecone/Chroma?

+

Answer: Standalone vector databases force dual-database synchronization (relational DB for users + vector DB for vectors). PostgreSQL with pgvector provides unified ACID transactions, user foreign keys, and vector search in one database.

Q3: Why chunk at 700 tokens instead of whole pages?

+

Answer: Embedding an entire 30-page document into one vector dilutes specific factual details. 700 tokens captures coherent semantic paragraphs. Overlapping chunks prevents sentences from being split in half across boundaries.

Q4: How do you prevent cross-user data leaks?

+

Answer: In RagService.java, all vector similarity queries enforce metadata->>'userId' = :authenticatedUserId derived from the validated JWT token, ensuring total multi-tenant data isolation.

Q5: What was the Supabase PgBouncer issue?

+

Answer: Supabase uses PgBouncer in transaction pooling. The PostgreSQL JDBC driver caches server-side named prepared statements (S_1), which collide across pooled connections. We resolved it by setting prepareThreshold=0.

Q6: What if the question isn't in the document?

+

Answer: The system prompt has a strict zero-hallucination constraint: "If the answer cannot be found in the provided snippets, state that the document does not contain this information."
